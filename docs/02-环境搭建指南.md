# 本地开发环境

体验完整功能时，使用 Docker Desktop 和 Compose v2 即可启动整套服务。首次体验请从[本地启动指南](20-本地容器化启动与验收.md)开始。下面的工具用于在宿主机阅读、构建和测试源码。

| 模块 | 工具 | 目录 |
| --- | --- | --- |
| Java 业务服务 | JDK 21、Maven 3.9+ | 项目根目录 |
| Python AI 服务 | Python 3.11、uv | `python-service/` |
| React 前端 | Node.js 24+、npm 11+ | `frontend/` |

## Java 和接口契约

在项目根目录用 IntelliJ IDEA 打开 `pom.xml`。运行 Java 测试时可以使用项目中的 Maven Central 配置：

```powershell
mvn -gs scripts/maven-delivery-settings.xml -s scripts/maven-delivery-settings.xml test
```

## Python 服务

在 PyCharm 中打开 `python-service/`。从项目根目录执行：

```powershell
cd python-service
uv sync --locked --python 3.11
uv run --locked python -m pytest -q
uv run --locked python ../contracts/validate_contracts.py
```

## 前端

在 VS Code 中打开 `frontend/`，从项目根目录执行：

```powershell
npm --prefix frontend ci
npm --prefix frontend run build
```

构建成功后，在一个终端启动预览：

```powershell
npm --prefix frontend run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

保留预览终端，在另一个终端从项目根目录运行模拟回归：

```powershell
npm --prefix frontend exec -- playwright install chromium
$env:DOCTRAIL_E2E_BASE_URL = 'http://127.0.0.1:4173'
npm --prefix frontend run test:e2e -- e2e/auth-role.spec.js e2e/design-refresh.spec.js
```

这两个测试文件会拦截 API 请求。完整测试集还包含需要真实服务和模型的 RAG 流程。运行应用所需的账号和密钥通过本机配置提供，模板见 [`.env.example`](../.env.example)。
