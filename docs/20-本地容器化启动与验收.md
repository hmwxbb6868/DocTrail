# 本地 Docker 启动与验证

本指南适用于首次启动和更新 DocTrail。配置、模型缓存准备好后，可从项目根目录用一条 Compose 命令构建并启动全部服务。

## 1. 前置条件

- Windows Docker Desktop已启动Linux容器后端，Docker Compose v2可用，具备拉取镜像、Maven Central和npm依赖的网络访问条件。
- 可以下载源码 ZIP 或克隆仓库。构建容器只需 Docker，Java、Maven 和 Node 由镜像构建环境提供。若自行下载模型缓存，需要 uv。
- 在解压或克隆后的项目根目录打开 PowerShell。该目录中应有 `docker-compose.yml` 和 `.env.example`。

## 2. 本机配置

已有 `.env` 时保留原文件；不存在时才创建：

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
notepad.exe .env
```

只在本机填写以下值，勿回传、截图或提交实际凭据：

| 变量 | 要求 |
| --- | --- |
| MYSQL_DATABASE、MYSQL_USERNAME | 非空；正式库通常为doctrail，禁止填入legacy库 |
| MYSQL_PASSWORD、MYSQL_ROOT_PASSWORD、REDIS_PASSWORD | 独立、非空的本机密码 |
| INTERNAL_TOKEN | 非空、高强度的内部共享密钥 |
| JWT_SECRET | 至少32个UTF-8字节 |
| DEMO_USERNAME、ADMIN_USERNAME | 各3–64个字符 |
| DEMO_PASSWORD、ADMIN_PASSWORD | 各至少6个字符且UTF-8总长度不超过72字节 |
| DEEPSEEK_API_KEY | readiness要求存在；不代表授权模型调用 |
| NGINX_HOST_PORT | 模板默认8080；本机验证使用18080 |

Compose固定容器服务名、端口、local存储和容器内路径，覆盖示例中的宿主开发默认值；不需要把示例中的127.0.0.1手动改成容器名。Java只允许预置账号登录，Compose关闭公开注册。不要设置真实OSS凭据来完成本地验证。

MySQL已有数据卷时，修改初始化密码变量不会重置库内密码。不要为修复配置错误直接删除卷。

## 3. 准备离线模型种子

构建镜像不会下载模型，启动时从宿主 `model-cache/` 预填 `model_cache` 命名卷。可将自己已验证的完整缓存放在仓库根目录，也可在允许联网的宿主准备：

```powershell
Push-Location .\python-service
try {
    uv sync --locked --python 3.11
    uv run --locked python scripts/verify_embedding.py --cache-dir ..\model-cache
} finally {
    Pop-Location
}
```

此步骤可能从HuggingFace下载公开模型，不调用DeepSeek；uv需已安装并加入PATH。本机若uv未加入PATH，可使用其实际安装路径，不能把特定用户的工具路径当成新机前置。

正式种子结构须包含：

```text
model-cache/models--BAAI--bge-small-zh-v1.5/
  snapshots/<revision>/...
  blobs/...
  refs/main
```

`refs`中的版本必须指向存在且完整的snapshot。验证输出应为dimension512、normalized=true。初始化只复制snapshots/blobs/refs，不复制锁目录和历史备份；正式Python使用CPU与离线模式，模型卷只读。模型文件不进Git。

## 4. 校验、构建与启动

只做解析校验，避免输出含密钥的展开配置：

```powershell
docker compose config --quiet
```

前置齐备后的一条启动入口：

```powershell
docker compose up -d --build --wait --wait-timeout 660
```

四个一次性服务只消费本地构建镜像，使用pull_policy: never，避免首次镜像不存在时误去远端仓库拉取doctrail-*:local并显示错误。必须保留上述--build或先显式构建Java/Python镜像；在镜像不存在时仅执行--no-build会失败。

首次需下载基础镜像、Python CPU依赖、Maven与npm依赖，网络慢时可能耗时较长。Java现直接执行含测试的package，使用BuildKit Maven依赖缓存与仓库提供的官方Central HTTPS设置，避免go-offline预取无关插件。下载失败时先查看具体错误，不用反复加`--no-cache`；缓存提高重建速度，仍不代替锁定版本和校验依赖完整性。

```powershell
docker compose ps -a
```

MySQL、Redis、Python、Java应healthy，Nginx应Up；data-volume-init、model-cache-init、auth-bootstrap、python-ready应Exited(0)。Java同时等待账号bootstrap和Python readiness；默认ready等待600秒。只有Nginx有宿主映射，例如127.0.0.1:18080->80/tcp。单独显示3306/tcp、6379/tcp是内部端口。

8080绑定被Windows拒绝时，不根据一条错误就断言具体占用进程。可在本机 `.env` 调整NGINX_HOST_PORT，再运行 `docker compose up -d nginx`，无需重建镜像。本项目已用18080验证。

## 5. 浏览器与业务链

运行 `docker compose port nginx 80` 查看实际入口。模板默认端口是 `8080`，下面以这个端口为例。

1. 访问 `http://127.0.0.1:8080/login`，使用demo账号登录。刷新后可恢复登录；刷新进入空白新对话时，在左侧选原会话读取历史。
2. 在独立Cookie环境访问 `/admin/login`，使用管理员账号登录，刷新管理仪表盘应保持登录。两个普通标签页或多个同类无痕窗口不保证身份隔离，可使用不同浏览器或普通/无痕两种环境。
3. 管理员访问 `/admin/knowledge` 上传自己有权使用的PDF/DOCX/TXT/Markdown。选择文件即上传，等待“已完成”。上传202仅表示接收，不能替代COMPLETED。失败时先看脱敏原因，勿盲目重传。
4. 如需验证知识问答，请针对已解析文档提一个可核对的问题，并检查回答与来源。问题和检索片段会发送给 DeepSeek，可能产生费用。
5. 刷新并打开原会话，确认回答、来源与消息数量保留；只读取历史，勿重发问题。
6. 管理员访问 `/admin/agent-runs`，核对相应run的knowledge_qa、COMPLETED、步骤和检索tool-call。标识应与原请求对应；不以新发一次问答代替查询审计。

入口 `/health/live` 应404，不公开Java/Python运维JSON。容器周期探针只用liveness；readiness可能修复FAISS，只在启动或诊断时低频调用。

## 6. 更新与保留卷重启

仅改前端时，在仓库根目录执行：

```powershell
docker compose build nginx
docker compose up -d --no-deps nginx
```

这只替换入口镜像和容器，不需要重建全部后端。单独重建Java容器造成IP变化时，应同步重启Nginx重新解析服务名。

保留卷的停止与恢复：

```powershell
docker compose stop nginx java python-service redis mysql
docker compose up -d --no-build
```

四个命名卷分别为mysql_data、uploads_data、faiss_data、model_cache。重启前后应比较数据库记录与快照、上传文件哈希、FAISS文件/活动版本、模型缓存指纹。readiness可能重建索引，因此仅看到READY不足以证明原索引文件直接保留。Redis为可丢失派生会话/缓存，不是消息历史真相。

## 7. 回归与交付记录

无真实模型调用的角色回归：

```powershell
$env:DOCTRAIL_E2E_BASE_URL = 'http://127.0.0.1:8080'
npm --prefix .\frontend run test:e2e -- e2e/auth-role.spec.js
```

该文件拦截全部API；整套 `test:e2e` 另含真实问答，未获授权时不要运行全部用例。Java/Python全量测试与契约校验仍需通过，具体结果及已知跳过项记录在当前进度。

本地容器化基线 `v3-deployed` 验证过登录、文档上传与解析、带来源的问答、历史会话恢复和保留卷重启。准新机演练复用了基础镜像或构建缓存。依赖风险和适用范围见[本地交付剩余风险评估](22-本地交付剩余风险评估.md)。

新版前端和仪表盘在现有本机环境完成构建、Compose 启动和统计核对。该记录的环境已具备配置、镜像和数据卷。
